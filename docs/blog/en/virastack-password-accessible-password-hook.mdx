A "show / hide" button on a password field looks like a few lines of `useState`. Then the list grows: a screen reader has to hear the button's state, the password should hide again on submit so a password manager saves the right value, and someone typing with Caps Lock on should be told. On top of that you want to rate the password, check that the confirmation matches, and run the same rules again on the server. You end up rewriting all of it in every project, and something always slips.

**ViraStack Password** (`@virastack/password`) puts that work into one React hook. It's headless: it hands you props for the input and the button, and the markup and styles stay yours. It has no dependencies; the hook is about 3 KB, and the strength engine only ships when you pass a policy.

## What it does

- **Visibility:** Adds `aria-pressed` and `aria-controls` to the button, hides the password on submit, moves focus back to the input after a click, and reports Caps Lock.
- **Strength:** Follows NIST SP 800-63B. The default policy asks for 15–64 characters and no composition rules; the level grows with length. It catches well-known passwords, repetition and personal information.
- **Confirmation:** `matchWith` checks that a second field repeats the first.
- **Server:** `@virastack/password/server` runs the same policy inside a Server Action.
- **Leaked passwords:** Optionally, `@virastack/password/pwned` looks the password up in Have I Been Pwned. It sends the first 5 characters of the SHA-1 hash, never the password.
- **Error keys:** It returns keys like `password.tooShort` and `password.mismatch` instead of messages, so the wording and translations stay yours.

## Install

```bash
npm install @virastack/password
```

React 18.2 or later is enough. React Hook Form 7.55+ is needed only if you bind the hook to it.

## The simplest version

For a plain show / hide toggle, call the hook with no arguments:

```tsx title="password-field.tsx"
import { useViraPassword } from "@virastack/password"

export function PasswordField() {
  const { inputProps, btnProps } = useViraPassword()

  return (
    <div className="relative">
      <input {...inputProps} placeholder="Your password" />
      <button {...btnProps} />
    </div>
  )
}
```

`btnProps` comes with eye icons. For text labels, use `icons`:

```tsx
const { inputProps, btnProps } = useViraPassword({
  icons: { show: "Show", hide: "Hide" }
})
```

## A sign-up form

A real sign-up form needs a policy, a personal-info check and a confirmation. Define the policy in its own file; the server will import it too:

```ts title="lib/password-policy.ts"
import { definePolicy } from "@virastack/password/strength"

export const policy = definePolicy() // NIST: 15–64 characters
```

Then bind the hook to React Hook Form, one entry per field, keyed by field name:

```tsx title="signup-form.tsx"
import { useForm } from "react-hook-form"
import { useViraPassword } from "@virastack/password"

import { policy } from "@/lib/password-policy"

export function SignupForm() {
  const form = useForm({ defaultValues: { email: "", password: "", confirm: "" } })

  const { password, confirm } = useViraPassword(form, {
    password: { policy, forbidden: ["email"] },
    confirm: { matchWith: "password" }
  })

  return (
    <form method="post" onSubmit={form.handleSubmit(console.log)}>
      <input type="email" autoComplete="username" {...form.register("email")} />

      <input {...password.inputProps} />
      <button {...password.btnProps} />
      <p {...password.strengthProps}>{password.strength?.level}</p>
      {password.capsLock && <p>Caps Lock is on</p>}

      <input {...confirm.inputProps} />
      <button {...confirm.btnProps} />
    </form>
  )
}
```

`inputProps` already includes `register()`, so spread it on its own. `forbidden: ["email"]` takes a field name: a password that is just the email's local part plus digits or symbols (`johnsmith1990` for `john.smith@…`) is rejected. `strengthProps` is a `role="status"` region, so screen readers announce the level as it changes. And `method="post"` matters: a form submitted before hydration never puts the password in the URL.

## How strength is measured

Length sets the level, not character classes: `fair` at the minimum length, `good` from 5 characters more, `strong` from 10 more. The checks look at the whole password after stripping digits, symbols and repetition. A few results with the default policy:

```ts
import { definePolicy, evaluate } from "@virastack/password/strength"

const policy = definePolicy()

evaluate("Summer2026!", policy)
// { level: "weak", valid: false, issues: ["password.tooShort", "password.common"] }

evaluate("correct horse battery staple", policy)
// { level: "weak", valid: false, issues: ["password.common"] }

evaluate("johnsmith1990", policy, { forbidden: ["john.smith@example.com"] })
// { level: "weak", valid: false, issues: ["password.tooShort", "password.containsPersonalInfo"] }

evaluate("quiet-harbour-lights", policy)
// { level: "good", valid: true, issues: [] }

evaluate("cold coffee on a quiet morning", policy)
// { level: "strong", valid: true, issues: [] }
```

"Summer2026!" has an uppercase letter, digits and a symbol, and it's still weak: 11 characters, and a pattern everyone uses. The famous "correct horse battery staple" is long enough but so well known that it's on the common list. "cold coffee on a quiet morning" is just lowercase words and spaces, and it's strong. That's NIST's point: a long phrase you can remember beats a short, complex one.

If you have a second factor (MFA), `definePolicy({ preset: "mfa" })` lowers the minimum to 8 characters.

## The same rules on the server

Client checks can be bypassed, so run the policy again in a Server Action:

```ts title="app/signup/actions.ts"
"use server"

import { validatePassword } from "@virastack/password/server"

import { policy } from "@/lib/password-policy"

export async function signup(formData: FormData) {
  const result = await validatePassword(formData.get("password"), policy, {
    forbidden: [formData.get("email")],
    confirm: formData.get("confirm"),
    pwned: { timeout: 3000 }
  })

  if (!result.valid) return { errors: result.issues }
  // result.password is normalized with the policy: hash it and create the user
  return { ok: true }
}
```

When the two passwords differ, you get:

```ts
// { valid: false, issues: ["password.mismatch"], level: "strong", … }
```

`pwned` asks Have I Been Pwned; a breached password gets `password.pwned`. If the lookup times out or fails, sign-up isn't blocked. Run it on the server: called from the browser, Have I Been Pwned sees the user's IP address.

The package's root entry is marked `"use client"`. In Server Components and Server Actions, import from `/server` or `/strength`.

## Error messages

The hook returns keys, not text. Map them to your own copy:

```ts
const messages: Record<string, string> = {
  "password.tooShort": "Use at least 15 characters",
  "password.common": "This password is too common",
  "password.containsPersonalInfo": "Don't use your name or email",
  "password.mismatch": "The passwords don't match",
  "password.pwned": "This password appeared in a data breach"
}
```

## With ViraStack Mask

[ViraStack Mask](/blog/virastack-mask-react-hook-form-input-masks) keeps its values in React Hook Form too, so both share one `useForm`. To put a toggle on a masked field (a PIN, say), spread both on the same input:

```tsx
const { pin } = useViraMask(form, { pin: { mask: "999999" } })
const pinToggle = useViraPassword({ autoComplete: false })

<input {...pin} {...pinToggle.inputProps} />
<button {...pinToggle.btnProps} />
```

One more thing: don't block pasting into password fields. Password managers rely on it.
